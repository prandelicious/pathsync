A. Rich TTY, Structured Plain Lines

TTY gets the dashboard. Plain output stays grep-friendly and line-oriented.

B. Same Layout Everywhere

Consistent visuals, but noisy and awkward in logs because every redraw becomes a frame.

Plain / redirected
copying files | 141/318 files | 58.2 GB / 133.0 GB

No target progress lines.
No per-target verification table.

C. Minimal Plain Output

Very quiet logs, but loses the multi-target confidence signal outside TTY mode.

My recommendation: A

  • It preserves a polished interactive UI without making logs unreadable.
  • Plain output should still include target progress and final target verification, but as parseable lines/tables.
  • This keeps tests simpler because non-TTY contracts can assert stable text tokens instead of exact frames.

Tradeoff

  • TTY and plain output have separate formatters, so tests need to cover both contracts.
