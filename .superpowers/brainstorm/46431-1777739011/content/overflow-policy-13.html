Show slow/failed/active rows first. More useful, but rows may reorder during the run.

My recommendation: A

  • The live UI should be stable; rows jumping around is visually expensive.
  • Workers are bounded by configured parallelism, so fixed visible rows work well there.
  • Target overflow is acceptable in live view because the final summary will show every target result.

Tradeoff

  • A hidden slow target might not be visible live unless we later add a specific attention override.
