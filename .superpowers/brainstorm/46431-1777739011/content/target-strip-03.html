Question 3: How much detail should the live target strip show?

The strip should reassure you that each target is moving, without turning the live view into a spreadsheet.

Targets
T7        71/159 copied   71 verified   0 failed
Archive   70/159 copied   70 verified   1 failed

A. Counts Only

Compact and stable. Good for confidence, weak for diagnosing slow or stuck targets.

Targets
T7        [█████████████                 ]  31.0 / 66.5 GB   78.4 MB/s   2 active
Archive   [███████████                   ]  27.2 / 66.5 GB   64.0 MB/s   1 active

B. Byte Progress + Rate

Best for seeing whether destinations are actually advancing and which target is lagging.

Targets
T7        [█████████████                 ]  71/159 copied   31.0 / 66.5 GB   78.4 MB/s
Archive   [███████████                   ]  70/159 copied   27.2 / 66.5 GB   64.0 MB/s

C. Full Mini Dashboard

Most complete, but it takes horizontal space and starts competing with the worker rows.

My recommendation: B

  • Per-target bytes and rate are the fastest way to spot a target that is falling behind.
  • Counts can stay in the final summary, where exact per-target correctness matters more.
  • The row stays readable if we cap target labels and hide the strip first on narrow terminals.

Tradeoff

  • It does not show exact verified counts during the run; that precision moves to the summary.
