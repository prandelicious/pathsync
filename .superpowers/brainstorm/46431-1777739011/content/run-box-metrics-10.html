Question 10: What should be permanent in the right Run box?

The Run box is the stable anchor across live and summary views. It should contain only metrics that are useful at a glance.

┌ Run ─────────────────────┐
│ Scanned    2,941         │
│ Planned    318           │
│ Copied     141           │
│ Verified   141           │
│ Failed     1             │
│ Bytes      58.2 / 133 GB │
│ Rate       142.4 MB/s    │
│ Elapsed    7m08s         │
│ ETA        8m46s         │
│ Targets    2             │
└──────────────────────────┘

A. Core Run Metrics Only

Stable, compact, and easy to scan. Worker counts stay out of the box.

┌ Run ─────────────────────┐
│ Scanned    2,941         │
│ Planned    318           │
│ Copied     141           │
│ Verified   141           │
│ Failed     1             │
│ Bytes      58.2 / 133 GB │
│ Rate       142.4 MB/s    │
│ Elapsed    7m08s         │
│ ETA        8m46s         │
│ Copy W     4             │
│ Verify W   2             │
│ Targets    2             │
└──────────────────────────┘

B. Include Worker Counts

Useful for debugging, but makes the box taller and mixes configuration with outcome metrics.

┌ Run ─────────────────────┐
│ Status     Copying       │
│ Phase      Large files   │
│ Scanned    2,941         │
│ Planned    318           │
│ Copied     141           │
│ Verified   141           │
│ Failed     1             │
│ Bytes      58.2 / 133 GB │
│ Rate       142.4 MB/s    │
│ Elapsed    7m08s         │
│ ETA        8m46s         │
│ Targets    2             │
└──────────────────────────┘

C. Include Status and Phase

More self-contained, but duplicates the left-pane header and phase line.

My recommendation: A

  • The Run box should be the run ledger: scanned, planned, copied, verified, failed, bytes, rate, elapsed, ETA, targets.
  • Worker counts are operational details already visible in the worker rows.
  • Keeping the box short gives more vertical room to workers, target strip, and failure details.

Tradeoff

  • If worker tuning becomes important later, worker counts can move into a debug/verbose mode.
