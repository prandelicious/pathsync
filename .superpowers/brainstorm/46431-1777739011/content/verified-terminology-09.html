Question 9: How should the UI name progress while verification is folded into workers?

During the run, a worker may hash, copy, then verify. The overall progress text should not overclaim before verification finishes.

Copying  [██████████                    ]  58.2 GB of 133.0 GB   ETA 8m46s

┌ Run ─────────────────────┐
│ Copied     141           │
│ Verified   141           │
│ Failed     1             │
└──────────────────────────┘

A. Keep Copied and Verified Separate

Overall says copying; the Run box shows both copied and verified counts as separate facts.

Verifying copy  [██████████                    ]  58.2 GB verified of 133.0 GB   ETA 8m46s

┌ Run ─────────────────────┐
│ Verified   141           │
│ Failed     1             │
└──────────────────────────┘

B. Treat Verified as the Main Progress

Emphasizes correctness, but can feel odd while workers are still actively copying.

Transferring  [██████████                    ]  58.2 GB processed of 133.0 GB   ETA 8m46s

┌ Run ─────────────────────┐
│ Done       141           │
│ Failed     1             │
└──────────────────────────┘

C. Use Generic “Processed/Done”

Avoids overclaiming, but hides the important distinction between copied and verified.

My recommendation: A

  • It is honest during the run: the app is copying, with verification folded into each worker.
  • Copied and verified counts remain explicit, so users can see correctness progress.
  • The final summary can switch emphasis to verified results once the run is complete.

Tradeoff

  • The Run box has one more metric, but that metric is important enough to keep.
