Question 11: What outcome language should the summary use?

The final header and target result labels should make the run outcome obvious without reading the whole table.

Pathsync (vlog)                                      VERIFIED
──────────────────────────────────────────────────────────────────────────────
Copying  [██████████████████████████████]  131.6 GB verified of 131.6 GB

Target Results
Target      Planned   Copied   Verified   Copy Fail   Verify Fail   Result
T7              159      159        159           0             0    verified
Archive         159      159        159           0             0    verified

A. Verified / Attention / Failed

Use correctness-focused language. Clean runs are `VERIFIED`; partial target issues are `ATTENTION`; systemic/copy failure is `FAILED`.

Pathsync (vlog)                                      COMPLETE
──────────────────────────────────────────────────────────────────────────────
Copying  [██████████████████████████████]  131.6 GB copied of 131.6 GB

Target Results
Target      Planned   Copied   Verified   Copy Fail   Verify Fail   Result
T7              159      159        159           0             0    success
Archive         159      159        159           0             0    success

B. Complete / Success / Failed

Conventional CLI wording. Familiar, but less explicit about verification being the trust boundary.

Pathsync (vlog)                                      COMPLETE WITH WARNINGS
──────────────────────────────────────────────────────────────────────────────
Copying  [███████████████████████████---]  129.5 GB verified of 131.6 GB

Target Results
Target      Planned   Copied   Verified   Copy Fail   Verify Fail   Result
T7              159      159        159           0             0    ok
Archive         159      157        157           1             1    warning

C. Complete / Warning / Error

Softens partial failures as warnings. Useful for batch tools, but can understate verification failures.

My recommendation: A

  • The whole feature exists to build trust that target files match the source signatures.
  • `VERIFIED` is a stronger and more accurate success state than `COMPLETE`.
  • `ATTENTION` avoids calling partial failure a success while still distinguishing it from systemic failure.

Tradeoff

  • It is slightly less conventional CLI language, but it better matches the product promise.
